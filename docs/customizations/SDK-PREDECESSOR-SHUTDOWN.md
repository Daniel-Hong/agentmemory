# Paired SDK predecessor shutdown

The initial SDK conversion allowed an SDK shutdown receipt only after start_attempted. The installed SDK predecessor could therefore be stopped and then rejected by the next update as though it owed a disk receipt. No operating attempt was made to force that path.

The development candidate now derives the predecessor kit from the existing hash-bound service ExecStartPre. It binds the root-owned reviewed kit/release, activation identity, installed package files, matching SDK profile, current version and loaded ExecStart/ExecStop/ExecStartPre. Proof is checked in preflight and immediately before service control. Main/worker/engine PID/start/boot identities are retained; PID rereads must match and the same proven PID tuple is used for receipt and all-gone checks. A discovered replacement-PID race has its own RED/GREEN regression. Verification-to-use cannot be made globally atomic against arbitrary concurrent system changes; unknown results remain refused/manual.

The change is candidate-scoped runtime code. There is no baseline schema or global enrollment policy change. Disk predecessors still require verified/synced disk receipts. SDK predecessors require completed=true, verified=false, completion=sdk, synced=false, zero mutation failures, a fresh worker receipt and every proven process gone. No forced kill, reset, data rewind, automatic old-writer restart or weakening of existing post-start rollback/recovery conditions is introduced.

Synthetic release/bootstrap/catalog/disk/rollback regressions and independent review cover missing/tampered contracts, wrong service/loaded override, code changes, process replacement, mismatched receipt and incomplete exit. A read-only comparison against current .33 protected code/loaded commands passed with zero service control. This is not an operating stop/deployment test.

The prior whole JS regression's index_publication certificate failure is separately retained. Fourteen relevant files are byte-identical to the baseline. A one-key fixture reproduces an existing disk fence race when a newer certificate forgets the touched revision before an older capture resumes. The actual full-run ordering was not recorded, so causality for that run is unconfirmed. Ordinary completion=sdk returns before that disk loop; this guard fix does not patch or hide the disk defect. No timeout/assertion was relaxed and no repeated full runs are used to declare that race resolved.

Upstream replacement: remove this candidate runtime extension when the normal release system supports equivalent explicit predecessor/candidate contracts and truthful SDK receipts with these refusal/identity tests.
