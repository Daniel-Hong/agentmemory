# daniel.6 — 운영 진행 현황과 대시보드 적용 경로

## 승인된 화면 구성

상단 상태 요약 → 단계별 남음·최근 완료·분당 완료·예상 시간·진행 상태 표 → 접힌 오류/공급자/세션 상세 순서다. 수집 저장·요약·압축·그래프·임베딩·기억 정리를 구분한다. 단계별 건수는 겹칠 수 있으므로 고유 기록 수나 전체 완료율로 표시하지 않는다. 일시정지는 기존 공통 제어를 사용하며 수집은 계속된다.

새 Codex 읽기 전용 분석 실행 버튼은 제거한다. 서버 API와 과거 분석 결과는 보존하고, 사용자가 과거 기록 보기를 선택했을 때만 조회한다. 운영 패널 초기 조회에서 Codex 분석 조회나 실행을 요청하지 않는다.

## 완료량과 예상 시간의 근거

수집은 기존 완료 카운터를 노출한다. 임베딩은 기존 엄격한 publication·fingerprint 검증과 retry 완료 지점에서만 완료 카운터를 증가시킨다. 공급자 응답·대기량 감소·삭제·실패·중복은 성공 처리량으로 세지 않는다. 두 카운터는 Worker별 UUID를 갖는 휘발성 메타데이터이며 재시작 시 새 집계를 시작한다. 운영 데이터 형식과 기존 retry 저장 방식은 변경하지 않는다.

브라우저는 기존 health/control/sessions 조회에서 얻은 완료량 표본만 최대 60개 보존한다. 2개 이상·60초 이상·실제 완료 증가가 있을 때 분당 속도를 계산한다. 5분 조회 간격에도 요청 지연을 고려해 이전 표본을 유지한다. Worker 재시작, 세션 구성 변경, 개별 카운터 감소, 조회 실패/오래된 상태, 백그라운드 보류에서는 표본 또는 계산을 무효화한다. 지원하지 않는 단계는 집계 미지원으로 표시한다.

현재 잔여량/최근 완료 속도로 단계별 예상 시간을 계산한다. 새 유입이 우세하거나, 최근 오류·공급자 대기·격리·보류가 있으면 시간을 보류하고 이유를 표시한다. 아직 끝나지 않은 한 작업을 정지라고 단정하지 않는다. 전체 파이프라인 완료 시각은 후속 작업과 미래 입력을 알 수 없어 제공하지 않는다. 새로 열린 화면은 관측 표본이 쌓일 때까지 측정 중이다.

## 업데이트 신뢰 경계

기존 대시보드 인증 API, 후보 목록, UUID 요청, root runner/systemd와 상태 이력을 재사용한다. 브라우저가 실행 경로·명령·URL을 정하지 못한다. 과거 outputs의 배포 스크립트는 사용자 쓰기 가능한 외부 코드를 연쇄 import하므로 root 후보로 그대로 등록하지 않는다.

새 kit는 검토 대상 runtime/helper와 tarball·manifest·baseline만 가진다. 준비 도구는 승인되지 않은 초안과 검토 양식을 만들며 승인 여부나 검토자를 자동으로 채우지 않는다. 관리자 검토 증거에 묶인 정확한 파일을 root 소유 snapshot으로 등록한 뒤 대시보드에서 선택한다. 설치 및 guard/archive 작업은 서비스 사용자 권한으로 수행하고 root는 고정 OS 작업만 수행한다. 기존 root helper/unit/sudoers 파일은 동일하면 유지한다.

정상 종료 저장 인증, 최신 private backup, 원본·커서·retry·제보 보존, 두 검증표, 실제 guard, archive 전체 read-back과 코드만 rollback을 충족해야 한다. root 준비/등록은 적용과 구분한다. 적용 명령 종료 0도 실제 capture/embedding 회복을 증명하지 않으므로 최종 인수는 별도다. 각 root 실행 코드 변경에는 명시적인 검토가 필요하며 임의 프로그램의 자동 승인을 제공하지 않는다.

## 검증과 운영 상태

이 버전은 daniel.5의 StateKV nullish 반환 계약 수정을 포함한다. .5를 이미 운영 적용했다고 가정하지 않으며 적용 baseline은 실제 .4 영수증으로 고정한다. 호환 훅 13파일이 동일하면 Ubuntu/Windows 재설치가 필요하지 않고 현재 retained .3 경로를 유지한다.

변경별 RED/GREEN, 실제 브라우저 데스크톱/모바일·키보드 및 합성 ETA 검증은 `outputs/operations-overview-daniel6-2026-10-20/`에 남긴다. 전체 suite, 빌드, 최종 패키지/격리 CLI, kit 거래·실패 시험 및 운영 인수 결과는 해당 증거가 생성된 뒤 별도 보고에 기록한다. 구현 중인 후보를 적용 완료나 queue 복구 완료로 보고하지 않는다. 기존 발행 묶음은 변경하지 않는다.

장기기억은 별도 수동 검토 대기이며 자동 저장·기존 기억 덮어쓰기를 하지 않는다. 체인지로그와 증거 파일은 구현/검증/등록/적용/인수를 구분해 보존한다.
