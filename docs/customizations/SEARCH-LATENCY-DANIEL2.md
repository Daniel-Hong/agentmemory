# 0.9.30-daniel.2 검색 지연 수정

2026-10-19. daniel.1의 개인 수정 후속이며 순정 그래프 검색 의미를 유지한다.

- 운영 REST 소문자 `personal`, includeLessons=false: 156ms. `AgentMemory personal`: 15초 시간 초과.
- 노드 31,466개(약11MB), 간선102,500개(약30MB)를 매 검색마다 SDK로 전체 전달한다. 파일 backend는 기존 namespace 스트리밍 파서를 사용해 로컬 읽기로 전환한다. 새 DB/마이그레이션/데이터 수정은 없다. Redis는 기존 SDK 경로를 유지한다.
- SDK가 확인한 미저장 set/update/delete를 overlay하고 디스크 반영을 확인하면 해제한다. 실패한 mutation은 불확실 상태로 차단하며 손상 파일을 부분 성공으로 취급하지 않는다.
- matching node마다 연결 인덱스를 재생성하던 동작을 검색당 1회로 변경한다. 탐색 순서와 점수 계산은 동일하다. 실제 자료를 별도 읽기 전용 프로세스에서 검색한 시간: 50,278ms → 5,021ms. 이 수치는 운영 API 최종 응답시간 인증이 아니다.
- 독립 리뷰: 100개 그래프×깊이4종×메서드2종의 이전/수정 결과·순서·문맥 동일. 기존 조회 동작을 유지하는 성능 수정이며 그래프를 비활성화하지 않는다.
- 한계: 전체 로컬 graph scan과 broad query traversal은 남아 있다. native graph query가 제공되면 이 reader를 대체한다. 모든 검색어의6초 마감 보장은 아직 없다.
- 배포·운영 API 인수·클라이언트 적용을 구분한다. 이미 발행한 daniel.1 묶음은 수정하지 않는다. 체인지로그 및 새 후속 배포 영수증을 참조한다.
- 장기기억 저장은 별도 수동 검토 대기다. 기존 기억·제보·원문을 삭제하거나 덮어쓰지 않는다.
