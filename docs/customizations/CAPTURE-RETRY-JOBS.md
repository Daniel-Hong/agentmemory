# 수집 재시도 서버 작업 — daniel.10

단건과 전체 모두 브라우저와 독립된 서버 작업이다. 기존 원문/inbox와 capture review를 재사용하며 새로운 namespace `mem:capture:jobs`에는 ID/상태/시각만 기록한다. 데이터 migration/root 실행/클라이언트 훅 변경은 없다.

- 전체는 접수 당시 dead만 최대10000개 snapshot하며 이후 새 격리는 포함하지 않는다. 초과 시413, 조용히 일부만 실행하지 않는다.
- 한 번에 작업 하나/항목 하나. 같은 UUID는 같은 작업이며 다른 UUID로 경쟁 접수해도 원래 작업에 영속 alias를 남긴다. 원래 작업 종료 후에도 alias는 다른 작업을 만들지 않는다.
- 요청 ID는 작업·대상별 최초 생성값을 유지한다. 실제 관측 존재를 확인하고 observation/review/inbox/event의 저장 인증 뒤에만 완료 체크포인트를 게시한다.
- 브라우저를 닫아도 서버 worker가 계속 처리한다. 서버 재시작은 같은 저장 작업을 이어간다. 수동 백그라운드 pause/배포 유지보수 pause는 존중하므로 재개 전에는 대기한다.
- 작업 중지는 다음 항목부터 시작하지 않는다. 이미 실행한 한 항목은 자동 재시도 예약을 포함해 최종 결과를 확인하고 멈춘다. 재실패는 점검 필요로 남기며 원문/이력을 삭제하지 않는다.
- 정상 종료는 worker의 다음 진입을 막고 현재 단위까지 drain한다. 완료 이력만 있고 실제 관측/원문이 없으면 성공으로 표시하지 않고 점검 필요로 남긴다.
- Viewer는 열려 있을 때2초마다 GET 상태 조회, 완료/중지 시 목록 자동 갱신, 중복 버튼 잠금, 성공/점검/제외/남은 건수 표시. POST 응답 유실 시 자동 재전송하지 않는다. 접수 미확인은 같은 요청 재전송 버튼으로 처리하며 이전 버전 pending도 같은 ID의 명시적 재전송을 지원한다.
- 단계별 처리 현황은 기본 접힘이며 열림/접힘을 자동 갱신 중 유지한다.

API (기존 auth/origin/JSON 경계 사용):

- GET `/agentmemory/capture/jobs?jobId=<UUID>`: 지정 작업(경쟁 alias도 원작업으로 해석) 또는 현재/최근 작업. 전체 대상 목록과 원문은 반환하지 않는다.
- POST `/agentmemory/capture/jobs`: `{requestId,all:true}` 또는 `{requestId,eventId,key?}`. 202 접수 결과; 명령 결과가 실제 관측 복구 완료라는 뜻은 아니다.
- POST `/agentmemory/capture/jobs/stop`: `{jobId}`. 중지 상태 반환. 기존 동기 `/capture/retry`는 호환을 유지한다.

검증 근거는 workspace outputs/capture-jobs-daniel10-2026-10-20/에 보존한다. TypeScript 기존24진단은 무오류가 아니며 baseline과 비교한다. 운영 전체 재시도/운영 적용은 검증 목적으로 실행하지 않는다. 장기기억은 수동 검토 대기다.

upstream이 같은 멱등/영속 작업·중지·원문/실저장 이력·재시작 보존을 제공하면 같은 회귀와 실제 엔진 시험으로 동등성을 확인하고 커스텀을 대체한다.

서버 worker의 조회/저장/인증/체크포인트 단계와 경과 시간을 상태에 포함한다. SDK의180초 호출 한도를 강제로 줄이거나 이미 시작된 쓰기를 병렬 재전송하지 않는다. 저장 확인 실패는 안전한 코드로 표시하고 같은 ID를 유지하며 다음 단위 시작을 보류한다.
