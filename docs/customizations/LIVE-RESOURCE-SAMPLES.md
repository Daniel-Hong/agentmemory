# Live health resource samples

The health route keeps its cached health/cpu record and adds optional `resourceSample`. The helper calls local `process.memoryUsage()` once after all existing async health/metrics/operational reads. Wall-clock milliseconds and process uptime bracket that call and the V8 heap-limit lookup. No extra SDK/KV query, state write, timer, model invocation, endpoint, authentication rule or server setting is introduced. A local sampling exception or invalid capture clock returns null without replacing health's established status/body.

Schema version1: pid, startedAtMs/finishedAtMs, uptimeStartSeconds/uptimeEndSeconds, and numeric memory heapUsed/heapTotal/heapLimit/rss/external/arrayBuffers. The interval is explicit; this is not a claim that cached CPU/worker/KV fields were collected at the same time. It is operational metadata, not source data or disk-commitment evidence.

The pure `scripts/personal-release/live-memory-observer.py` consumes the actual JSON body and a caller-bound expected PID, receipt time and host availability. Kernel boot/start/socket/store identity remains the authenticated caller's responsibility. It refuses unavailable, stale (>15sec), future, internally inconsistent (>1sec capture or >50ms wall/uptime-duration disagreement), changed-duplicate and out-of-order samples, without cached fallback. PID identity alone does not prove an epoch. At most six fresh samples are retained. Duplicates do not grow trends; absolute checks still run on each poll.

Absolute checks preserve heap>=70%, hostAvailable<8GiB, any SDK mutation failure and non-normal memory pressure. Sample refusal is unsafe, not permission to continue. No control request, service action, file write, credentials, process signal, inspector or heapdump exists in this tool.

Trend output is explicitly shadow-only and never authorizes resume. A measured heap drop resets the current allocation segment; it does not establish GC occurrence or absence of a rising long-term low-water mark. The maximum positive adjacent slope, count of positive slopes and the 120sec80% warning are reported. With a caller-supplied hypothetical drain budget, headroom is computed **to80%**, after that budget+poll10sec+margin20sec+sample age. No default production drain maximum is inferred from one observed30sec drain. This target differs from the earlier offline sketch's headroom-to100%; they are not equivalent policies. Neither proposal has been promoted into an operating guard. No automatic recovery/retry is enabled.

Registered-handler tests exercise actual local sampling, delayed dependencies, unchanged auth/cached health/KV/SDK counts and error compatibility. JSON is passed into the real isolated Python CLI to validate its wire contract, old-server rejection and stale/PID cases. Pure tests cover duplicates, absolute checks, release resets, malformed/huge values and bounded finite calculations. These tests do not claim a running production workload, engine durability, OOM prevention, a proven maximum drain duration or actual dashboard rendering.

Upstream replacement: remove this optional compatibility helper only when the official API supplies an equivalent same-process fresh interval and the wire/freshness/protection tests remain true. Data, source archives, failure history and current capture contracts are unrelated and remain preserved.
