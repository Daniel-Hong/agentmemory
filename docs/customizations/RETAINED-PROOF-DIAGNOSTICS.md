# Bounded retained-proof diagnostics — preparation only

The .65 retained retry path intentionally requires exact equality between a newly computed Float32 embedding, the retained WAL row and the loaded vector/session, followed by the existing current checkpoint/receipt proof. An ordinary `VECTOR_RECOVERY_PAUSED` retry result does not distinguish fresh-byte mismatch from physical proof rejection. Earlier fresh provider bytes were not retained, so the earlier cause remains unknown.

This draft adds `indexPersistence.retainedProofLastCheck` to the existing status object. Existing health/status/snapshot callers already pass that object through. It is null until a known retained ID is checked or when local diagnostic sampling becomes unavailable, holds only one final result, and returns a defensive copy. Unknown IDs never replace it. The operation distinguishes capture-pending validation from retained-publication validation. A publication result includes only a newly observed same-ID inner capture proof reason/code, so an earlier verified result cannot label a later rejection.

The fixed shape contains the known retained ID, operation and reason enum; fresh/loaded byte and session match booleans; retention readiness; stopped/storage hold/generation/recovering/blocked/paused flags; pending log/log-chain/dirty counts; revision-change flag; and an allowlisted physical proof error code. A null match/revision field means it was not observed for that path. Capture-pending has no fresh provider bytes, so `freshBytesMatch` is null; its session match refers to the supplied selected session. No vector, base64, source text, free-form exception, stack or secret is retained. Unknown errors map to `UNCLASSIFIED_PROOF_ERROR`.

Diagnostics sample local state at the final decision, without further SDK or file reads/writes. The snapshot is observational and is not an atomic proof, a new receipt or a success override. Diagnostic collection is best effort and cannot change a verification decision. The original current/matches predicates, reconciliation arguments, exact comparisons, retained mutation guard, SDK completion and retry/backoff remain unchanged. Physical proof still retains every existing refusal. No new endpoint, background work, inference, replay, data repair or migration is introduced.
