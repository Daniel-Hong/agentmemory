# Snapshot JSON stream boundary

Baseline .35 observed serialize / RangeError after observation reads completed. Exact native message is intentionally unavailable: do not claim string-length overflow is proven. Export currently stringifies the entire archive; restore captures all git stdout then parses one string. Both impose a whole-archive string boundary.

Minimum implementation: keep the same JSON structure/order/pretty representation for JSON-backed records. Frame top-level arrays and observation session arrays, use native JSON serialization per record with the original property/index key, and send strings directly to existing private temp-file publication. Retain file fsync/close/rename/directory sync/Git order. No new storage, engine, guard, client or timeout changes.

Restore frames the same sections from Git stdout, validates all JSON including unknown fields and trailing input, preserves duplicate-key last-value and __proto__ own-key semantics, and verifies child close/code0 before any existing restore write. Parsed archive objects remain in memory as before; this is not a global transaction. A record must still fit native JSON limits. Cancellation before publication preserves existing snapshot and cleans the temp; after atomic publication the prior Git commit remains the recovery point, matching existing semantics.

Use only small synthetic data and temporary Git repositories. Prove reduced synthetic native-string cap rejection in old paths, byte-equivalent export, old/new restore compatibility, UTF-8/chunk boundaries, malformed/duplicate/unknown data, child failure/cancel cleanup, and existing snapshot retention for generator/write/fsync/rename failures. No production reads/resume, large workload or real engine runs.

Final review boundaries: known container/record IDs and the existing graph validator run before export and before restore writes. Unknown JSON is syntax-validated but ignored as before; duplicate keys use last values; own __proto__ remains data. UTF-8 replacement follows legacy stdout decoding while BOM is preserved then rejected as legacy JSON.parse did. Native per-record toJSON keys/undefined omission are retained.

Git child failure or cancellation never starts restore writes. SIGTERM is requested once and the operation stays pending until actual close; TERM-ignoring children can delay cancellation/resource recovery indefinitely, matching the previous no-timeout Git path. No force kill, timeout increase or cleanup-success claim before close. Temp unlink is attempted even if close itself reports failure. Cleanup failure can supersede the initial error; both remain failure, not success.

The parsed archive still resides in heap; individual records still require native JSON string capacity. Existing restore is a merge, not an all-or-nothing transaction after SDK writes begin. Post-rename errors cannot undo the published working file; prior committed Git snapshots remain, matching the existing publication boundary. No arbitrary-size or immediate-cancellation guarantee.
