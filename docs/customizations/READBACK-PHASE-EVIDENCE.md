# Readback phase evidence (development only)

The deployed failures show admission waits and unfinished physical reads, but do not distinguish parsing from stream/stat/close waits. A stable synthetic 45MB parse is not evidence of production recovery. This diagnostic increment complements 3a4e6e5's operation/stage checkpoint instead of changing recovery budgets.

The reader exposes optional current progress. The shared physical read retains one snapshot; caller cancellation samples it before removing that caller. A scan's full namespace validation, expected value, inode signature, fsync, final signature and original deadline are unchanged. Direct observation consumers without this observer do not retain extra progress. There are no extra file reads, timers, socket connections or log writes in the instrumentation.

`processingMs` is elapsed wall time for scanning/decoding/JSON parsing, entry callbacks and any scheduling inside those callbacks. It is not exclusive CPU. `streamMs`, `statMs`, `openMs`, and `closeMs` include event-loop/libuv scheduling. Process CPU and event-loop active/idle cover the physical read window and can include concurrent consumers, engine SDK work and GC; they cannot independently attribute GC or disk latency. Shared followers see the physical read's window, including time before joining. Complete means reader cleanup ended; `complete` separately means the namespace scan validated. `readerFailurePhase` retains a failed stage through cleanup. Neither means the enclosing certificate succeeded.

The health measurement retains the first eight compact readback failures per process without replacement, plus an explicit omitted count. Existing recent32/15-minute traces keep their coverage contract. The same whitelisted compact summary is stored with an unresolved item's existing `lastVerificationFailure` checkpoint, surviving trace eviction and coordinator restart without another write. New fields contain only fixed phase enums, durations, byte counts and completion flags. No keys, namespace tokens, paths, raw errors, values or user identifiers. Old failures and historical190 unknown attempts are not reconstructed, reset or acknowledged.

Validation: test-first regressions for safe observer errors, live open/stat/stream/close waits, partial abort, shared caller cancellation, diagnostic clock failure, malformed namespace, bounded trace retention and checkpoint restart; single-fork storage/recovery regressions. Tiny actual installed-engine test used a separate temporary HOME/store/loopback port and one worker, verified actual SDK state plus disk certification, and confirmed child processes exited and listener closed. No actual search index or production load was tested. Full/browser/load suites remain excluded by the user's low-I/O constraint.

Operating deployment is not performed. A server-only update/restart would be necessary to observe natural production failures with these fields; collector/admin permissions, storage layout and deadlines need no change. It must preserve current holds, item proof budgets, circuit state and all originals. A previously exhausted item must not be reset to obtain a sample. Replace this customization when upstream exposes equivalent body-free durable read diagnostics and retains evidence across failed recovery attempts with the same tests.
