# SDK queue progress, client-only .61 preparation

The .60 server fixes retained-inbox transport size, but the installed .55 SDK-v2 client can stop making progress once its private reference queue reaches the 5 MiB admission limit. Atomic pending-to-sending and sending-to-held/retry replacement previously demanded additional quota that admission could consume. Completed-manifest replacement had the same problem at the 256 MiB original limit. A selected delivery also loaded every pending original, and each queue budget recursively measured unrelated originals while holding the shared lease.

This change keeps the existing 256 MiB original and 5 MiB reference admission limits. Only replacement of an existing reference may use an additional 8 KiB (one reference block and one conservative parent-directory block); completing an existing manifest may use an additional 68 KiB (the 64 KiB manifest limit and one directory block). No new source or reference can consume that transition workspace. All preserved partial/crash files still count, so exhausted workspace fails explicitly without deletion or quota bypass. These are conservative logical charges, not filesystem hard quotas. Each namespace is measured separately.

Direct delivery reuses the existing selected-reference send path. The atomic claim preserves current/dead owner fencing, pending backoff and explicitly selected held restoration. Listing pending references validates their private manifest metadata and skips completed sources without reading all source chunks. The selected source still receives complete canonical-envelope/chunk/hash verification before claim and POST. Unselected chunk corruption is discovered when that item is selected, not by listing unrelated entries. Unknown transport/reply outcomes remain held; SDK acknowledgement remains distinct from disk durability.

Originals retained after failed enqueue remain preserved and are not silently auto-replayed. A reviewed recovery can enumerate manifest metadata, exclude completed/conflicted or unknown-send entries, then use the existing selected public SDK path for exact target/source recovery. No direct original/ref rewrite, lease removal, global reset or deletion is part of this change.
