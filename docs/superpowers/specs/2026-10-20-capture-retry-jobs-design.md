# 수집 재시도 서버 작업

사용자 승인: 중복 클릭 방지·완료 자동 갱신·전체 재시도. 창을 닫아도 서버에서 계속 처리하며 명시적 중지 버튼을 제공한다.

기존 KV 및 capture retryOne/실저장 확인/키별 mutex를 재사용한다. 단건과 전체 모두 인증된 비동기 작업으로 접수한다. 동시에 하나의 작업만 실행하고 활성 작업이 있으면 새 요청 대신 같은 작업을 돌려준다. 작업 UUID는 멱등 키이며 대상별 UUID도 최초 접수 때 영속 보존한다. 같은 작업 UUID의 범위 변경은 거부한다.

전체는 시작 시 dead만 snapshot하며 최대10000개를 초과하면 명시적으로 거부한다. 원문은 기존 inbox에만 보관하고 작업은 ID·상태·시각만 저장한다. 각 항목은 한 번에 하나씩 진행한다. 작업 저장 인증 후 재시도를 시작하고, 기존 저장 영수증과 복구 이력으로 완료/다시 격리/이미 처리됨을 판정한다. 일시적 요청 실패는 같은 항목 ID로 재확인한다. 자동 재시도 예약은 최종 성공과 구별한다.

GET/POST /agentmemory/capture/jobs 및 POST /agentmemory/capture/jobs/stop을 추가한다. GET은 현재/최근 작업 또는 jobId 지정 상태만 반환하며 대상 전체는 노출하지 않는다. POST는 requestId와 all:true 또는 eventId/key를 whitelist한다. stop은 jobId를 검증하며 다음 항목부터 시작하지 않고 이미 시작된 항목이 저장 결과를 확인하면 stopped로 전환한다. 중지된 작업 이력은 남기고 새 전체 요청은 남아 있는 dead만 대상으로 한다.

기존 capture controller의 timer/start/stop/drain에 worker를 연결한다. backgroundTask로 수동 pause와 작업 수를 반영하며 서버 종료 시 다음 항목 시작을 금지하고 현재 단위는 정상 drain한다. 재시작 시 persisted active job을 같은 대상 UUID로 이어간다. UI 창 수명과 worker 수명은 독립이다.

UI는 접수 전 ID를 보존하고 버튼을 잠근다. 불확실 응답에는 GET만 자동 조회하며 같은 ID를 재사용한다. 창이 열려 있는 동안 2초 간격으로 중복 GET 없이 추적하고 완료 시 목록을 갱신한다. 닫으면 브라우저 조회만 중지한다. 재방문 시 서버 활성 작업을 조회한다. 전체 요청에는 대상 건수와 시작 확인을 표시한다. 작업 중지 버튼은 진행 중인 한 건은 끝낸다는 설명을 포함한다.

검증: 중복/다중탭 요청, 동일 ID 범위변경, 작업 snapshot, 원문 보존, 부분 실패, 기다림/실저장 확인, stop 경합, 재시작/동일ID, 저장 실패 후 복구, pause/정상 종료, auth/whitelist, 실제 모바일 브라우저 자동 갱신·중복 클릭·창 닫기 후 서버 지속. 운영 전체 재처리는 사용자 버튼 전에는 실행하지 않는다. 새 의존성/root 실행 변경/클라이언트 훅 변경/장기기억 자동 저장 없음.
