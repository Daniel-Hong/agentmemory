# Recovery first-use and controls implementation plan

Goal: make the existing opt-in quarantine reconciliation usable after a verified local engine cold start, without rebooting the PC or clearing uncertainty by assertion.

Design choice: use OS process identities and listening-socket ownership, not elapsed time, normal exit alone, a new privileged controller or direct data scans. The existing CLI/service lifecycle remains responsible for stopping/starting processes after separate operating approval. This code only observes the resulting boundary. Local native engine only; unavailable/remote/forwarded/shared/migrated contexts remain unsupported.

1. Add a small native engine evidence reader: known iii.pid candidate, Linux boot/host identity, PID+start ticks, iii executable and ownership of the configured loopback SDK LISTEN socket. Test PID reuse, denied reads, wrong endpoint, same-engine restart, old-worker survival, actual old-process absence and endpoint replacement using synthetic proc fixtures.
2. Bind writer lease metadata to host/endpoint/current engine+worker identity (v3). First execution records but does not admit. Subsequent admission requires retained verified clean identity or a proven same-host boot/cold-engine boundary and terminated old worker. Revalidate current endpoint ownership during automatic admission. Preserve unknown records as blocked; do not add process signaling or mark-safe command.
3. Persist requested enabled state in the existing recovery control record. Default OFF, point-read initialization, bounded existing certification. Disabling stops local admission immediately; enabling is rejected unless writer/background/memory conditions pass. Add an authenticated strict-boolean POST under capture, no permission expansion and no force option. Keep storage/manual/deployment/memory holds independent.
4. Add a toggle and safe blocked reason to the existing capture dialog using existing token/HTTP helper. Unknown HTTP outcomes prompt status refresh, never blind reissue. Add small single-fork controller/API/UI contract tests and independent review.
5. Run low-load targeted regression/build/generator/doc checks, record all deferred full/browser/real-engine tests. Push personal only. No operating deployment, activation, restart, process stop or data experiment.

Completed development validation: 19 single-fork test files / 227 cases passed; build and skills checks passed. Native engine identity/socket behavior, store binding, unknown writer boot persistence, authenticated controls, ON/OFF races, holds and UI contracts have synthetic coverage. Independent review found no remaining important issue within the stated local participating-writer support contract. Full aggregate/browser/installed-engine/load checks remain deliberately deferred. No operating action performed.
